## Goal and acceptance criteria

The Console saves valid selected pairs from the engine feed as matches and shows them in a Matches tab on Event Detail.

- Migration `0013` adds `event_matches` and `event_match_feed_cursors`, is generated by `pnpm db:generate`, reviewed, and **not applied** to any database without explicit approval.
- Feed sync is idempotent per `(recommendationId, kind)` and per canonical pair; A+B equals B+A; replays never reactivate a revoked match; the cursor advances only after a page is applied.
- Invalid entries are stored revoked with a reason; revoked entries revoke stored matches.
- `GET /api/events/{eventId}/matches` and `.../matches/{matchId}` are limited to active Owners/Organizers of the event's organization.
- The Matches tab lists matches (active/revoked filter), opens a `ConsoleDialog` detail, and has loading, empty, error and "engine not connected" states. No copy implies acceptance or a meeting.
- `pnpm verify` and `pnpm build` pass; skipped suites are reported.

**Out of scope:** F10, F11, F12, F13, manual pairs, messaging, engine changes, cron sync.

**Tenants and roles:** see the specification. Owner and Organizer only.

## Decisions and discoveries

- **2026-10-19: the feed is fetched outside the database transaction** (deviation from the draft plan, which fetched under the event lock). The sync reads the cursor, fetches, then locks the event, re-reads the cursor and applies the page only if the cursor is unchanged. A network call under the event lock would block organizer writes for up to the timeout.
- **2026-10-19: profile-version staleness does not revoke** (deviation from the draft plan's "not older than expectation"). The engine keeps recommendations across profile edits, so the Console only rejects pinned versions newer than its own.
- **2026-10-19: the status trigger uses `checked_through_run_id`** on the cursor row so a poll syncs once per newly finished run, not on every poll.
- **2026-10-19: Matches tab hidden for non-managers.** `activeTab` falls back to Overview when `?tab=matches` is requested without `attendees.canManage`; the API enforces the real rule.
- **2026-10-19: query key is `["event-matches", eventId]`**, matching the other event panels; actor scoping is by the server-side authorization and per-session query client.
